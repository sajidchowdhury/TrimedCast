    57→    57→    57→### 1.1 Q1: What product should be ordered?
    58→    58→    58→
    59→    59→    59→**Logic:** A product appears on the recommended order list when:
    60→    60→    60→
    61→    61→    61→```
    62→    62→    62→Current Available Stock < Reorder Point
    63→    63→    63→```
    64→    64→    64→
    65→    65→    65→Where:
    66→    66→    66→
    67→    67→    67→```
    68→    68→    68→Reorder Point = (Daily Consumption Rate × Lead Time) + Safety Stock
    69→    69→    69→```
    70→    70→    70→
    71→    71→    71→**Filterable dimensions:**
    72→    72→    72→| Filter | Values | Use Case |
    73→    73→    73→|--------|--------|----------|
    74→    74→    74→| Season | `winter`, `summer`, `monsoon`, `pre_winter`, `all_season` | "Show me winter-critical items" |
    75→    75→    75→| Motorcycle Model | `CD70`, `Pulsar150`, `Platina100`, etc. | "Only CD70 parts" |
    76→    76→    76→| Category | `brake_system`, `chain_sprocket`, `engine`, `electrical`, `body`, `riding_gear` | "Brake parts only" |
    77→    77→    77→| Urgency | `critical`, `high`, `normal`, `low` | "What needs ordering NOW?" |
    78→    78→    78→| CNY Risk | `true`, `false` | "Which orders have CNY risk?" |
    79→    79→    79→| Shipment Mode | `sea`, `air` | "Air-ship the urgent ones" |
    80→    80→    80→
    81→    81→    81→**Output:** Filterable Recommended Order List (sorted by urgency descending)
    82→    82→    82→
    83→    83→    83→### 1.2 Q2: What quantity should be ordered?
    84→    84→    84→
    85→    85→    85→**Core formula:**
    86→    86→    86→
    87→    87→    87→```
    88→    88→    88→Recommended Qty = max(EOQ, (Forecasted Demand + Safety Stock) - Current Stock - Pending Orders)
    89→    89→    89→```
    90→    90→    90→
    91→    91→    91→**Constraints applied in order:**
    92→    92→    92→
    93→    93→    93→```
    94→    94→    94→┌────────────────────────────────────────────────────────────────┐
    95→    95→    95→│  1. Supplier MOQ:   qty >= MOQ    (cannot order below minimum) │
    96→    96→    96→│  2. Warehouse Cap:  qty <= Max Stock - Current Stock            │
    97→    97→    97→│  3. Overstock:      If current > max_stock, qty = 0 (draw down)│
    98→    98→    98→│  4. Seasonal Cap:   qty <= seasonal_demand_ceiling              │
    99→    99→    99→└────────────────────────────────────────────────────────────────┘
   100→   100→   100→```
   101→   101→   101→
   102→   102→   102→### 1.3 Q3: WHEN should the product be ordered?
   103→   103→   103→
   104→   104→   104→**This is the single most valuable algorithm in the entire system.**
   105→   105→   105→
   106→   106→   106→The Order Trigger Date accounts for:
   107→   107→   107→- ✅ Manufacturing lead time (supplier-specific)
   108→   108→   108→- ✅ Shipment time (sea or air route)
   109→   109→   109→- ✅ Customs clearance time (Chittagong port or Dhaka airport)
   110→   110→   110→- ✅ Chinese New Year shutdown impact
   111→   111→   111→- ✅ Seasonal demand acceleration/deceleration
   112→   112→   112→- ✅ Safety buffer before stock hits critical level
   113→   113→   113→
   114→   114→   114→**Why this is so valuable:** A BD motorcycle parts importer who orders too early ties up capital in warehouse inventory. One who orders too late faces stockouts during peak season. The precise trigger date **maximizes cash flow efficiency while minimizing stockout risk** — and that is worth the entire SaaS subscription.

   272→   272→   272→### 2.6 Lead Time Variability Model
   273→   273→   273→
   274→   274→   274→Lead times are NOT deterministic. The system models them as distributions for Monte Carlo simulation:
   275→   275→   275→
   276→   276→   276→```python
   277→   277→   277→from dataclasses import dataclass
   278→   278→   278→from typing import Optional
   279→   279→   279→
   280→   280→   280→@dataclass
   281→   281→   281→class LeadTimeDistribution:
   282→   282→   282→    """
   283→   283→   283→    Probabilistic model of each lead time component.
   284→   284→   284→    Used for Monte Carlo simulation of order arrival dates.
   285→   285→   285→    """
   286→   286→   286→    # Manufacturing
   287→   287→   287→    mfg_best: int = 75       # Best case (days)
   288→   288→   288→    mfg_likely: int = 90     # Most likely (days)
   289→   289→   289→    mfg_worst: int = 120     # Worst case (days)
   290→   290→   290→    
   291→   291→   291→    # Shipment (Sea)
   292→   292→   292→    ship_sea_best: int = 45
   293→   293→   293→    ship_sea_likely: int = 52
   294→   294→   294→    ship_sea_worst: int = 65
   295→   295→   295→    
   296→   296→   296→    # Shipment (Air)
   297→   297→   297→    ship_air_best: int = 5
   298→   298→   298→    ship_air_likely: int = 8
   299→   299→   299→    ship_air_worst: int = 12
   300→   300→   300→    
   301→   301→   301→    # Customs (Sea/Chittagong)
   302→   302→   302→    customs_sea_best: int = 7
   303→   303→   303→    customs_sea_likely: int = 10
   304→   304→   304→    customs_sea_worst: int = 18
   305→   305→   305→    
   306→   306→   306→    # Customs (Air/Dhaka)
   307→   307→   307→    customs_air_best: int = 2
   308→   308→   308→    customs_air_likely: int = 3
   309→   309→   309→    customs_air_worst: int = 5
   310→   310→   310→
   311→   311→   311→    def total_sea_best(self) -> int:
   312→   312→   312→        return self.mfg_best + self.ship_sea_best + self.customs_sea_best  # 127
   313→   313→   313→    
   314→   314→   314→    def total_sea_likely(self) -> int:
   315→   315→   315→        return self.mfg_likely + self.ship_sea_likely + self.customs_sea_likely  # 152
   316→   316→   316→    
   317→   317→   317→    def total_sea_worst(self) -> int:
   318→   318→   318→        return self.mfg_worst + self.ship_sea_worst + self.customs_sea_worst  # 203
   319→   319→   319→    
   320→   320→   320→    def total_air_best(self) -> int:
   321→   321→   321→        return self.mfg_best + self.ship_air_best + self.customs_air_best  # 82
   322→   322→   322→    
   323→   323→   323→    def total_air_likely(self) -> int:
   324→   324→   324→        return self.mfg_likely + self.ship_air_likely + self.customs_air_likely  # 101
   325→   325→   325→    
   326→   326→   326→    def total_air_worst(self) -> int:
   327→   327→   327→        return self.mfg_worst + self.ship_air_worst + self.customs_air_worst  # 137
   328→   328→   328→```
   329→   329→   329→
   330→   330→   330→**P90 lead times** (90% of orders arrive within this time):
   331→   331→   331→```
   332→   332→   332→  Sea P90:  ~175 days (use this for conservative planning)
   333→   333→   333→  Air P90:  ~115 days (use this for conservative air planning)
   334→   334→   334→```

   338→   338→   338→## 3. Chinese New Year (CNY) Impact Model
   339→   339→   339→
   340→   340→   340→### 3.1 CNY Shutdown Facts
   341→   341→   341→
   342→   342→   342→> This is the single biggest disruption to BD–China motorcycle parts supply chain. Every year, importers who fail to plan for CNY face 2–3 month stockouts. **TrimedCast is the first system to model this explicitly.**
   343→   343→   343→
   344→   344→   344→```
   345→   345→   345→  ┌─────────────────────────────────────────────────────────────────────┐
   346→   346→   346→  │  CHINESE NEW YEAR — THE ANNUAL SUPPLY CHAIN BLACK HOLE            │
   347→   347→   347→  │                                                                     │
   348→   348→   348→  │  • Chinese factories shut down for 2–4 weeks around Lunar New Year │
   349→   349→   349→  │  • No new production starts during the shutdown window              │
   350→   350→   350→  │  • Existing production may pause mid-way                            │
   351→   351→   351→  │  • Post-CNY restart is gradual (factories don't all restart Day 1) │
   352→   352→   352→  │  • Effective delay: 20–30 days added to any order touching CNY     │
   353→   353→   353→  │  • Pre-CNY rush: Suppliers prioritize older orders, new orders     │
   354→   354→   354→  │    placed in December/January may get delayed further               │
   355→   355→   355→  │                                                                     │
   356→   356→   356→  └─────────────────────────────────────────────────────────────────────┘
   357→   357→   357→```

   359→   359→   359→### 3.2 CNY Risk Detection Algorithm
   360→   360→   360→
   361→   361→   361→```python
   362→   362→   362→from datetime import date, timedelta
   363→   363→   363→from dataclasses import dataclass
   364→   364→   364→from typing import Optional
   365→   365→   365→
   366→   366→   366→@dataclass
   367→   367→   367→class CNYRisk:
   368→   368→   368→    """Result of CNY overlap analysis."""
   369→   369→   369→    has_risk: bool
   370→   370→   370→    overlap_days: int
   371→   371→   371→    original_trigger_date: Optional[date]
   372→   372→   372→    revised_trigger_date: Optional[date]
   373→   373→   373→    strategy: str           # 'before_cny', 'after_cny', 'none'
   374→   374→   374→    additional_delay_days: int  # Extra days added to lead time
   375→   375→   375→    explanation: str
   376→   376→   376→
   377→   377→   377→
   378→   378→   378→def check_cny_risk(
   379→   379→   379→    order_date: date,
   380→   380→   380→    mfg_days: int,
   381→   381→   381→    cny_start: date,
   382→   382→   382→    cny_end: date,
   383→   383→   383→    buffer_days: int = 5,  # Days before CNY when factories start winding down
   384→   384→   384→) -> CNYRisk:
   385→   385→   385→    """
   386→   386→   386→    Check if the manufacturing period overlaps with CNY shutdown.
   387→   387→   387→    
   388→   388→   388→    Manufacturing period: order_date to (order_date + mfg_days)
   389→   389→   389→    CNY shutdown: cny_start to cny_end
   390→   390→   390→    
   391→   391→   391→    Factories start winding down `buffer_days` before cny_start,
   392→   392→   392→    so effective CNY impact window is (cny_start - buffer) to cny_end.
   393→   393→   393→    
   394→   394→   394→    Args:
   395→   395→   395→        order_date: When the order would be placed
   396→   396→   396→        mfg_days: Manufacturing lead time in days
   397→   397→   397→        cny_start: First day of CNY factory shutdown
   398→   398→   398→        cny_end: Last day of CNY factory shutdown (factories restart next day)
   399→   399→   399→        buffer_days: Pre-CNY wind-down period (default 5)
   400→   400→   400→    
   401→   401→   401→    Returns:
   402→   402→   402→        CNYRisk with overlap analysis and resolution strategy
   403→   403→   403→    """
   404→   404→   404→    # Effective CNY window (includes pre-CNY wind-down)
   405→   405→   405→    effective_cny_start = cny_start - timedelta(days=buffer_days)
   406→   406→   406→    
   407→   407→   407→    # Manufacturing period
   408→   408→   408→    mfg_start = order_date + timedelta(days=2)  # 2 days order processing
   409→   409→   409→    mfg_end = mfg_start + timedelta(days=mfg_days)
   410→   410→   410→    
   411→   411→   411→    # Check overlap between manufacturing period and effective CNY window
   412→   412→   412→    overlap_start = max(mfg_start, effective_cny_start)
   413→   413→   413→    overlap_end = min(mfg_end, cny_end + timedelta(days=3))  # +3 for gradual restart
   414→   414→   414→    
   415→   415→   415→    if overlap_start < overlap_end:
   416→   416→   416→        overlap_days = (overlap_end - overlap_start).days
   417→   417→   417→        
   418→   418→   418→        # Determine best strategy
   419→   419→   419→        # Strategy A: Can we complete manufacturing before CNY starts?
   420→   420→   420→        latest_start_before_cny = effective_cny_start - timedelta(days=mfg_days) - timedelta(days=2)
   421→   421→   421→        
   422→   422→   422→        if order_date <= latest_start_before_cny:
   423→   423→   423→            strategy = 'before_cny'
   424→   424→   424→            additional_delay = 0
   425→   425→   425→            explanation = (
   426→   426→   426→                f"Manufacturing overlaps CNY by {overlap_days} days. "
   427→   427→   427→                f"However, ordering by {latest_start_before_cny} ensures "
   428→   428→   428→                f"manufacturing completes before CNY shutdown."
   429→   429→   429→            )
   430→   430→   430→        else:
   431→   431→   431→            strategy = 'after_cny'
   432→   432→   432→            # Full CNY delay: shutdown period + gradual restart
   433→   433→   433→            cny_shutdown_days = (cny_end - effective_cny_start).days + 3  # +3 restart
   434→   434→   434→            additional_delay = cny_shutdown_days
   435→   435→   435→            explanation = (
   436→   436→   436→                f"Manufacturing overlaps CNY by {overlap_days} days. "
   437→   437→   437→                f"Cannot complete before CNY. Effective delay: {cny_shutdown_days} days. "
   438→   438→   438→                f"Recommend ordering after CNY ({cny_end + timedelta(days=1)})."
   439→   439→   439→            )
   440→   440→   440→        
   441→   441→   441→        return CNYRisk(
   442→   442→   442→            has_risk=True,
   443→   443→   443→            overlap_days=overlap_days,
   444→   444→   444→            original_trigger_date=order_date,
   445→   445→   445→            revised_trigger_date=None,  # Set by caller based on strategy
   446→   446→   446→            strategy=strategy,
   447→   447→   447→            additional_delay_days=additional_delay,
   448→   448→   448→            explanation=explanation,
   449→   449→   449→        )
   450→   450→   450→    
   451→   451→   451→    # No overlap — safe
   452→   452→   452→    return CNYRisk(
   453→   453→   453→        has_risk=False,
   454→   454→   454→        overlap_days=0,
   455→   455→   455→        original_trigger_date=order_date,
   456→   456→   456→        revised_trigger_date=None,
   457→   457→   457→        strategy='none',
   458→   458→   458→        additional_delay_days=0,
   459→   459→   459→        explanation="Manufacturing period does not overlap with CNY shutdown.",
   460→   460→   460→    )
   461→   461→   461→```

   463→   463→   463→### 3.3 CNY Resolution Strategies
   464→   464→   464→
   465→   465→   465→```
   466→   466→   466→  ┌─────────────────────────────────────────────────────────────────────────┐
   467→   467→   467→  │                                                                         │
   468→   468→   468→  │  STRATEGY A: ORDER BEFORE CNY (Preferred)                               │
   469→   469→   469→  │  ──────────────────────────────────────                                 │
   470→   470→   470→  │  Place order early enough that manufacturing completes before CNY.      │
   471→   471→   471→  │  Required: order_date ≤ cny_start - mfg_days - buffer                  │
   472→   472→   472→  │  Pro:  No delay, goods arrive on original schedule                      │
   473→   473→   473→  │  Con:  Requires earlier capital outlay, may increase holding cost       │
   474→   474→   474→  │                                                                         │
   475→   475→   475→  │  STRATEGY B: ORDER AFTER CNY (Fallback)                                 │
   476→   476→   476→  │  ─────────────────────────────────────                                  │
   477→   477→   477→  │  Accept the delay. Place order after CNY ends.                          │
   478→   478→   478→  │  order_date = cny_end + 1                                               │
   479→   479→   479→  │  Adds CNY shutdown period (~25-35 days) to effective lead time          │
   480→   480→   480→  │  Pro:  No rush, standard order process                                  │
   481→   481→   481→  │  Con:  Stockout risk if safety stock is insufficient during CNY period  │
   482→   482→   482→  │                                                                         │
   483→   483→   483→  │  STRATEGY C: PARTIAL ORDER (Critical items only)                        │
   484→   484→   484→  │  ─────────────────────────────────────                                  │
   485→   485→   485→  │  Order critical/high-margin items before CNY (Strategy A)              │
   486→   486→   486→  │  Order non-critical items after CNY (Strategy B)                       │
   487→   487→   487→  │  Pro:  Balances capital efficiency with stockout prevention             │
   488→   488→   488→  │  Con:  Two shipments, more logistics complexity                         │
   489→   489→   489→  │                                                                         │
   490→   490→   490→  │  STRATEGY D: AIR ROUTE ESCAPE (Emergency)                               │
   491→   491→   491→  │  ─────────────────────────────────────                                  │
   492→   492→   492→  │  If stockout is imminent and CNY blocks sea route,                      │
   493→   493→   493→  │  switch to air route to reduce shipment time by ~44 days               │
   494→   494→   494→  │  Pro:  Fastest resolution                                               │
   495→   495→   495→  │  Con:  8x freight cost — use only for high-margin/critical items       │
   496→   496→   496→  │                                                                         │
   497→   497→   497→  └─────────────────────────────────────────────────────────────────────────┘
   498→   498→   498→```
